# Comment Rules

## 基本规则

为每一个新写或修改过签名/行为的函数创建文档注释。只约束本次触碰到的函数，不为了补齐历史遗留注释而批量修改无关代码。

## 注释内容

- 用文档注释描述函数做什么，而不是逐行复述实现。
- 注释应贴近函数声明，并使用当前语言或项目现有的文档注释风格。
- 简单函数使用简短的一句话说明。
- 如果函数执行的任务相对复杂，使用多行注释说明核心流程、关键副作用、边界条件或调用约束。
- 不要写空洞注释，例如“处理数据”“执行函数”。

## TypeScript 规则

在 `.ts`、`.tsx`、`.vue` 中的 TypeScript 代码块，以及其他 TypeScript 类型文件中：

- 省略 `@param` 参数注释，除非项目现有局部风格强制要求。
- 优先让类型签名表达参数和返回值信息。
- 可以保留必要的 `@returns`、`@throws`、`@deprecated` 等标签，但仅在它们提供类型签名无法表达的信息时使用。

## 示例

```ts
/**
 * 计算当前列表中可展示的结果数量。
 */
export function getVisibleCount(items: Item[]) {
    return items.filter((item) => item.visible).length
}
```
