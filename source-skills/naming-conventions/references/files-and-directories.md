# 文件与目录命名

按用途和约定逐段判断路径，扩展名和位置可辅助判断。

- 保留工具、框架或仓库约定的默认路径、名称和结构，例如 `vite.config.ts`、`package.json`、`.gitignore`、`README.md`、`AGENTS.md`、`page.tsx` 和 `[id]/`。`.github/workflows/build-and-test.yml` 的目录由平台规定，文件主体由项目命名。
- 保留交付要求指定的名称或路径。用户、项目或同类交付物约定中文名时，沿用如 `docs/发布说明.md` 的写法，各段按各自约定。普通英文文档可用 `release-notes.md`。
- 生成物、依赖和第三方内容沿用来源的命名。项目自主命名的源码、组件、样式、测试、脚本、资源和文档默认用 `kebab-case`。

约定不清时查目录说明、同类文件、工具配置和引用方。用户指定的名称与加载约定冲突时，先查工具能否配置自定义路径。无法同时满足时，说明冲突并确认路径。

可自主命名的目录段和文件主体用小写英文字母和数字，多词以单个 `-` 连接。名称说明用途，例如 `user-profile/`、`request-client.ts`、`user-avatar.vue` 或单词名 `utils/`。保留扩展名及约定的点分后缀，如 `.test.ts`、`.module.css`、`.d.ts`。工具经显式配置读取自定义路径时，主体可按此规则命名，如 `image-build.config.ts`。

重命名前检查目标路径冲突、公开路径、路由和外部链接。更新导入、再导出、文档链接和配置引用，运行相关检查。
