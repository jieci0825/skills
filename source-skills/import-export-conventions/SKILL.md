# 导入导出规范

按实际 ES Module 语法处理静态导入、导出及公开入口。Vue、Svelte 等文件的各脚本块分别处理，类型语法只用于支持 TypeScript 的脚本块。沿用项目的路径解析、格式化和框架约定。

## 导入

- 静态导入分为公共依赖 → 项目内部依赖 → 纯类型，非空组之间空一行。值导入按解析来源归组，公共组优先放核心框架，内部组先项目级路径，再相对路径。同组按逻辑组织，可沿用项目的字母排序配置。
- 同源值和类型分开写。纯类型用独立的 `import type` 放在末组，有运行时用途的绑定用普通导入。
- 整理导入、判断来源或处理加载顺序时读[导入分组](references/import-order.md)，保留初始化、模块求值和样式覆盖所需的顺序。

## 导出

- 内部模块优先具名导出，框架要求或既有公开契约可用 `export default`。
- 业务 API 具名导出请求函数，入口用 `export * as xxxApi from './domain'` 聚合。调用方具名导入 `xxxApi`，以 `xxxApi.method()` 调用。
- 独立工具函数从入口显式具名导出，同一对象或同类操作的高内聚工具可用命名空间，如 `storage.get()`。
- 模块外部优先走公开入口，内部直接引用实现。为明确的公开边界设置入口，显式列出成员。
- 入口按具名值 → 命名空间 → 纯类型再导出，非空组之间空一行。实现文件可在声明处导出。
- 公开类型从所属入口具名导出，再导出用 `export type { Name } from './module'`，私有类型就近定义。

增改业务 API、工具函数、公开入口或再导出时读[模块导出](references/module-exports.md)。拆分值与类型、调整公开类型或处理双重含义的符号时读[类型导入与导出](references/type-import-export.md)。

规范用于新增代码和本次涉及的语句。调整入口前检查调用方、公开名称和路径、循环依赖及模块求值顺序。兼容性与运行时行为优先于排布，范围外的问题可在审查结果中指出。
