# 导入导出规范

本 Skill 约束 ECMAScript 模块的静态导入、导出和公开入口。按实际使用的语法判断适用范围。Vue、Svelte 等文件中的各个脚本块分别处理，TypeScript 类型语法只用于支持它的脚本块。沿用项目已有的路径解析、格式化和框架约定。

## 导入

- 静态导入依次分为公共依赖、项目内部依赖、纯类型导入。相邻的非空分组之间留一个空行。
- 公共依赖组优先放核心框架，内部依赖组优先放项目级路径，再放相对路径。同组按逻辑组织，字母排序可沿用项目配置。
- 纯类型使用独立的 `import type`，统一放在最后。同一来源的值和类型分开写。具有运行时用途的绑定使用普通导入。
- 按解析后的模块来源归组。保证初始化、模块求值及样式覆盖所依赖的顺序，必要时保留原有排布。

## 导出

- 项目内部模块优先使用具名导出，框架要求或已有公开契约允许使用 `export default`。
- 业务 API 实现具名导出请求函数，公开入口以 `export * as xxxApi from './domain'` 聚合。调用方从入口具名导入 `xxxApi`，使用 `xxxApi.method()` 调用。
- 独立工具函数通过入口显式具名导出。围绕同一对象或同类操作的高内聚工具集合可以使用命名空间，例如 `storage.get()`。
- 纯类型以具名形式公开，二次导出用 `export type { Name } from './module'`。公开类型从所属模块的入口暴露，私有类型就近定义。
- 模块外部优先走公开入口，模块内部直接引用实现文件。为明确的公开边界设置入口，明确列出要公开的成员。
- 入口的再导出依次为具名值、命名空间、纯类型组，非空组之间留一个空行。普通实现文件可在声明处直接导出。

## 按需查阅

- 整理导入块、判断路径来源或处理有顺序依赖的加载时，读 [导入分组](references/import-order.md)。
- 新增或修改业务 API、工具函数、公开入口和再导出时，读 [模块导出](references/module-exports.md)。
- 拆分值与类型、调整公开类型或处理同时有值和类型含义的符号时，读 [类型导入与导出](references/type-import-export.md)。

## 修改边界

对新增代码和本次涉及的语句应用规范。调整现有入口前，检查调用方、已公开的名称和路径、是否形成循环依赖，以及模块求值顺序。兼容性与运行时行为优先于排布，超出本次范围的问题可在审查结果中指出。
