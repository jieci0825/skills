# Git 提交规范

在当前任务对应的 Git 工作树创建一次普通的本地提交。暂存区已有改动时，以当前暂存内容为提交范围。暂存区为空时，以本次对话中可确认的功能改动为范围。

## 执行流程

1. 检查仓库状态并阅读 [暂存与提交范围](references/staging-scope.md)。根据暂存区状态决定是否暂存文件。遇到未解决的冲突或进行中的合并、变基等操作时，先明确当前请求是否包含继续该操作。
2. 用 `git diff --cached --stat` 和 `git diff --cached` 核对实际准备提交的内容。暂存区没有可提交的改动时，说明原因并结束。根据暂存差异撰写 [中文提交信息](references/commit-message.md)。
3. 提交前复核暂存范围，运行不带路径参数的 `git commit`，让 Git 从暂存区生成提交。提交失败时检查错误及当前仓库状态，沿用项目的提交检查与签名要求。
4. 确认生成了新的提交，核对实际提交的内容和剩余的工作区状态，向用户报告提交哈希和标题。本地提交完成后结束。

## 按需查阅案例

- 对照不同暂存状态下的正确操作和中文提交信息时，读 [Good 案例](references/good-examples.md)。
- 判断哪些操作会扩大提交范围，或检查提交信息的常见错误时，读 [Bad 案例](references/bad-examples.md)。
