# Bad 案例

## 已有暂存改动，又从工作区取内容

`src/login.ts` 已暂存登录修复，工作区中还有未暂存的日志调整。

- `git add -- src/login.ts` 把同一文件里的日志调整也加入暂存区。
- `git commit -m 'fix(登录): 修复会话过期后的跳转' -- src/login.ts` 按路径取工作区内容，日志调整也会进入提交。

## 暂存区为空，把已有改动一起纳入

本次只实现订单状态筛选并新增测试。`src/order-filter.ts` 还含一处旧改动，仓库另有一份未跟踪的草稿。

- 在仓库根目录运行 `git add .` 会把旧改动和草稿也加入暂存区。
- `git add -- src/order-filter.ts tests/order-filter.test.ts` 虽然指定了相关文件，仍会把实现文件里的旧改动一并暂存。

## 提交信息格式或内容不符合要求

- `feat[订单]：支持按状态筛选订单` 误用了方括号和全角冒号。实际标题使用 `feat(订单): 支持按状态筛选订单`。
- `feat(订单): add status filter` 的描述使用了英文，中文标题应说明具体做了什么。
- `chore: 更新代码` 无法说明加入了订单状态筛选，类型也没有体现新增功能。
- 标题写了 `feat(订单): 支持按状态筛选订单`，正文只写“新增订单状态筛选功能”。正文重复标题，省略即可。

## 提交完成后继续推送

本地提交生成后再执行 `git push` 会向远端发布改动，超出了本 Skill 的执行范围。
