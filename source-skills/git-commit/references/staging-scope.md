# 暂存与提交范围

用 `git status --short` 和 `git diff --cached --name-status` 判断有无可提交的暂存改动。`git status --short` 的前两列分别是暂存区和工作区状态，同一文件可同时有两类改动。

## 暂存区已有改动

保留用户选中的全部文件和差异块，包括与本次对话无关的暂存内容。用不带路径的 `git commit` 仅提交暂存区，保留未暂存改动和未跟踪文件。

## 暂存区为空

1. 根据本次对话的编辑记录、已知基线和当前差异确认范围，可包含功能实现及直接相关的测试、配置和交付文档。其他已有改动和临时文件留在工作区。
2. 仅在整个路径的改动均确认属于本次对话时按路径暂存。用 `git --literal-pathspecs add -A -- <路径>` 可处理新增、修改和删除。移动文件时同时检查源路径和目标路径。
3. 同一文件混有既有改动时，按差异块暂存，如用 `git --literal-pathspecs add -p -- <路径>` 选择本次改动，可拆分的先拆分。无法可靠分离或确认归属时，说明文件和原因，请用户确认范围。

暂存前复查暂存区仍为空，暂存后检查完整的 `git diff --cached`。若有新改动进入暂存区，先核对来源和范围再继续。
