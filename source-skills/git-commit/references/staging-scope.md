# 暂存与提交范围

从 `git status --short` 和 `git diff --cached --name-status` 判断暂存区是否已有可提交的差异。`git status --short` 的前两列分别显示暂存区和工作区状态。一个文件可以同时有已暂存和未暂存的改动。

## 暂存区已有改动

直接提交现有暂存内容。保留用户已选择的文件和差异块，包括与本次对话无关但已暂存的内容。工作区中的未暂存改动和未跟踪文件保留原状态。即使同一个文件还有未暂存的修改，也直接用不带文件路径的 `git commit`。

## 暂存区为空

1. 从本次对话中的编辑记录、已知基线和当前差异确认功能范围。功能实现及其直接相关的测试、配置或交付文档可以一同提交。其他已有改动和临时文件留在工作区。
2. 仅对已确认整份改动都属于本次对话的路径执行按路径暂存。可用 `git --literal-pathspecs add -A -- <路径>` 处理新增、修改和删除。移动文件时确认源路径和目标路径都已纳入检查。
3. 同一个文件混有已有改动时，按差异块暂存，例如用 `git --literal-pathspecs add -p -- <路径>` 选出本次的改动。若同一差异块还能拆开，先拆分后选择。无法可靠分离或确认归属时，说明具体文件和原因，并请用户确认范围。

暂存前重新确认暂存区仍为空，暂存后检查完整的 `git diff --cached`。如果过程中发现有新的改动进入暂存区，先核对其来源和提交范围，再继续提交。
